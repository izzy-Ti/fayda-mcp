# Fayda QR Trusted Key Source, Lifecycle & Distribution Specification

This document details the source of truth, key lifecycle, distribution mechanisms, and trust bundle management for Fayda National ID QR code verification, per the Fayda MCP QR addendum and Ethiopian National ID standards.

---

## 1. Official Key Source & Authority

The digital signatures on physical Fayda National ID QR codes are generated by the **National ID Program of Ethiopia (NIDP)**.

- **Issuing Authority**: National ID Program (Fayda / NIDP).
- **Official Public Key Distribution**:
  - Published via official portals such as `id.gov.et/scanId` and `id.et/scanid`.
  - Distributed within the official Fayda verification mobile applications (e.g. *Fayda Verify* and official partner SDKs like Telebirr).
  - Provisioned out-of-band to enterprise verifiers and verifier backend systems as trusted X.509 certificates / PEM public key bundles.
- **Root of Trust**: Offline National ID Root and Issuing Intermediate Certificates.

---

## 2. Trust Isolation: QR Keys vs eSignet OIDC JWKS

A critical security requirement is the complete separation of offline QR public keys from online eSignet OIDC signing keys:

```
┌─────────────────────────────────┐       ┌─────────────────────────────────┐
│     Fayda eSignet OIDC JWKS     │       │     Fayda QR Trusted Bundle     │
│   (https://esignet.fayda.et)    │       │     (id.gov.et / Operator)      │
├─────────────────────────────────┤       ├─────────────────────────────────┤
│ • Dynamically rotated via JWKS  │       │ • Managed offline trust bundle  │
│ • Validates ID token / UserInfo │       │ • Validates printed QR cards    │
│ • Contains 'kid' in header      │       │ • Header contains NO 'kid'      │
│ • Online TLS retrieval          │       │ • Operator-pinned PEM/JWK keys  │
└─────────────────────────────────┘       └─────────────────────────────────┘
```

> **Security Rule**: eSignet JWKS endpoints must **never** be used to verify physical QR code signatures, and QR certificates must **never** be used to validate eSignet OpenID Connect ID tokens.

## 3. Key Lifecycle & Rotation Management

1. **Long-Lived Signing Keys**:
   Unlike short-lived web sessions, physical national ID cards are printed and held by citizens for multi-year validity periods. Consequently, Fayda QR card-signing public keys have extended lifecycles (typically 3 to 10 years).
2. **Key Rotation & Multi-Key Bundles**:
   Because the Version-4 QR protected header (`{"alg": "RS256"}`) omits the Key ID (`kid`), a verifier cannot look up a key by an explicit ID in the header. The verification engine must therefore support **trusted key bundles**:
   - The verifier attempts verification against the active operator-approved public key(s).
   - If multiple keys are active (e.g. during a planned cross-year rotation), the engine evaluates candidates in the trusted bundle until a valid signature match is achieved or all candidates fail.
3. **Revocation & Compromise Policy**:
   If an issuer signing key is retired or revoked, the operator updates their trusted key bundle file (`FAYDA_QR_KEY_BUNDLE_PATH`).
4. **Fails Closed**:
   If no trusted QR public keys are configured, or if the signature does not match any key in the bundle, verification returns `unverified` with `credential_signature_valid = false`. The engine never trusts an unsigned or unverified credential.

---

## 4. Key Formats Supported

The library accepts operator-approved QR public keys in any of the following formats:
- **PEM Encoded Public Keys**: Standard PKCS#8 or SubjectPublicKeyInfo `-----BEGIN PUBLIC KEY-----`.
- **X.509 Certificates**: Standard `-----BEGIN CERTIFICATE-----` certificates issued by the National ID authority.
- **JWK / JWKS Key Bundles**: Static JSON Web Key Set containing RSA public keys.
